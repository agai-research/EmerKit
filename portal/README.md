# EmerKit portal

**Pages.** *Plan my learning* is the learner page: one field, a plain-language plan, a picture of the path and its tools (savable as an image), and a spoken summary. *Expert view* shows how the plan was computed, with charts and the identifiers of the language-model calls. *How it works* explains the approach with the figures of the paper. *Tool registry* is a dashboard of the registries with charts and the search of the official MCP Registry. *Settings* holds the API key, the model, a connection test, and the composition parameters. *About* presents the article and its authors (set `EMERKIT_REPO_URL` when building to show the GitHub link).

A web application that runs EmerKit on learning requests and explains the approach step by step: decomposition of the request,
typed workflow and its validation, candidates retrieved from the registry, behaviour inferred under uncertainty, check of the data
flows against the norms, exact composition of the toolkit (or the minimal conflict), revision of the workflow, and the guarantee.
It also explains the approach, lets you browse the registries (and search the official MCP Registry), the norm base, and your
history of runs.

## What runs where
* **In the browser, live:** the request phase of EmerKit (`portal/engine.js`): rule-based or LLM workflow generation, validation and
  repair, candidate retrieval, flow check, exact composition by enumeration with conflict explanation, backtracking, substitution.
  `portal/tests/check_engine.mjs` checks it against the Python implementation of the paper on 550 tasks: same feasibility, same
  optimal objective, same minimal conflicts in every case (`python portal/tests/export_cases.py && node portal/tests/check_engine.mjs`).
* **Offline, once:** the preparation phase (`portal/build_bundle.py`): capability extraction, behaviour inference, conformal
  prediction sets at nine levels, calibrated levels, description similarities, for two registries: the EmerKit registry of the paper
  (163 synthetic tools with ground truth) and its extension with the 6,044 real tools of the Toucan MCP catalogue.
* **Language model:** with an Anthropic API key entered in the page, the request is decomposed and the workflow generated by the
  chosen Claude model. Without a key, keyword matching and the rule-based generator are used.

## Language models
*Settings* offers two providers: Anthropic Claude (API key; Haiku, Sonnet, Opus, or any other model identifier) and any
OpenAI-compatible server, for example a model downloaded and run locally with Ollama (`ollama pull qwen3:8b`, server address
`http://localhost:11434/v1`). Every plan is generated by the language model by default; when it cannot be reached, the portal asks
whether to use the rule-based method. Each call is limited to 90 seconds.

## Demo video
`docs/EmerKit_portal_demo.mp4` (about three minutes) shows a live run with Claude: settings and connection test, a learner request,
the plan and the tools, step alternatives, the expert view, the approach, the registry, and the About page.

## Run it on your computer (recommended)
```
python portal/serve.py          # then open http://localhost:8000
```
`serve.py` (standard library only) serves the page and relays, from your computer, the calls to the Anthropic API and to the official
MCP Registry. Browsers block such calls from a web page when the organization of the key forbids them (error "CORS requests are not
allowed for this Organization") or when the registry does not allow cross-site requests. You can also set `ANTHROPIC_API_KEY` in the
environment instead of typing the key in the page.

Opening `portal/index.html` directly from disk also works, with the rule-based generator and the prepared registries.

## Publish on GitHub Pages
Push the repository, then in *Settings > Pages* choose *GitHub Actions*; `.github/workflows/pages.yml` publishes `docs/`. On the
public site, visitors can enter their own key; the call goes from their browser to api.anthropic.com and works when their
organization allows browser access. Otherwise they can run the portal locally as above.

## Rebuild
```
python portal/build_bundle.py   # preparation phase -> portal/bundle.json
python portal/build_app.py      # inlines bundle and engine -> portal/index.html and docs/index.html
```
